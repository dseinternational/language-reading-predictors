**Date:** 2026-08-20. A full code review of the intention-to-treat (ITT) statistical models — the single-outcome `itt` family (LRP-RLI-ITT-001–030 and companions 108/113/114/129), the `joint` family that shares the ITT id space (012/015/016/115 and the LKJ dependence companions 215/216/315), and everything they execute: run-plan resolution, data preparation, the model factories, the likelihood links, the floor rule, the reporting/estimand layer, diagnostics and the convergence gate, sub-fits, the release layer, the phoneme-blending link-sensitivity bundle, the word-reading missingness bundle, the prior-sensitivity sweep producer, and the report partials. The review checked both functional correctness (indexing, alignment, provenance, file IO) and statistical correctness (estimands, priors, links, bounds arithmetic, diagnostics policy).

## Method

The core layers were read line by line (`itt.py`, `pipelines/itt.py`, `pipelines/joint.py`, `build_itt_model`/`build_joint_model` in `factories.py`, `likelihood.py`, `floor.py`, `priors.py`, the average-marginal-effect core in `reporting.py`, `predicted_scores.py`, `sensitivity.py`, `scripts/tau_prior_sensitivity.py`, `_setup.qmd`, `_results_itt.qmd`, `_results_floored.qmd`). Four parallel review passes covered the 38 model modules against the registry, the preprocessing layer, the diagnostics/sub-fit/release layer, and the blending/missingness/audit modules. Load-bearing claims were re-verified directly against the code, `git log`, the raw `data/rli_data_long.csv`, and the fitted `-reporting` artefacts on disk. The ITT-related test files (`test_itt_run_plan`, `test_itt_pipeline`, `test_itt_audit`, `test_itt_missingness`, `test_blending_sensitivity`, `test_floor`, `test_floor_prior_sensitivity`, `test_predicted_scores`, `test_joint_run_plan`) all pass on the reviewed tree.

**Headline verdict:** no confirmed error was found in any published number, estimand, prior, or diagnostic. The findings below are a release-policy enforcement hole, a dropped reader-facing caveat, one unverified measurement constant, one latent data-alignment bug, and a cluster of latent configuration traps and documentation drift.

## What was positively verified

- **Estimand arithmetic.** `reporting._itt_ame_draws` removes exactly the per-row treatment contribution (`eta0 = eta − delta·G`, with `delta` covering the constant `tau`, the age-varying `tau_i`, and any interaction moderators) and averages the counterfactual difference per posterior draw. The three-choice guessing-floor link (`mu = 1/3 + 2/3·expit`, `likelihood.py`) is applied to both counterfactual arms before differencing, so LRP-RLI-ITT-108's items-scale effect is the correct expected-observed-score contrast; the intrinsic two-thirds compression relative to the latent probability is visible in the fitted bundle and explained in the report. Every downstream consumer (ROPE summary and sensitivity, predicted scores, arm overlap, prior pushforward) routes through this one core or a guard-tested mirror, and the drift-guard tests pass.
- **Data path.** `phase_mode="itt"` loads the randomised t1→t2 window only, one row per child, failing loudly on duplicate child/time rows and group changes; no code path lets post-crossover waves into an ITT fit. Arm recoding (raw 1/2 → `G` = 1/0, positive = intervention benefit) is consistent across the loader, `data_variables.py`, the audit constants, and the report labels, matches the CONSORT 28/26 analysed split, and is pinned by a test. The pre-score transform is the Haldane–Anscombe empirical logit, finite and antisymmetric at the score bounds, sharing one denominator with the likelihood and the floor threshold; fractional, negative, or above-ceiling counts are rejected before any transform.
- **Floor rule.** A missing baseline is never treated as floored (`np.isclose(NaN, floor)` is false); the missing-eligibility bounds and the same-estimand transition-missingness bounds in `floor.py` compute sharp Manski-style extrema correctly on both the archived and full-randomised scopes (checked case by case); the at-risk row count is cross-checked against the eligibility table at runtime.
- **Convergence gate.** The gate scans the union of all free random variables and the curated family list, filtered to names in the posterior — so Hilbert-space Gaussian-process, LKJ, and non-centred parameters cannot pass unseen. Thresholds are the house ones (R-hat ≤ 1.01, min bulk/tail effective sample size ≥ 400, per-chain BFMI ≥ 0.3 failing closed on NaN, zero divergences), computed unrounded, and there is deliberately no code path that can mark a divergent fit "qualified" — qualification remains a manual, `METHODS.md`-governed act.
- **LOO and posterior-predictive checks.** Joint fits sum pointwise log-likelihood within child before PSIS, giving genuine leave-one-child-out; per-outcome predictive checks never pool different denominators; the floor-rule check correctly switches to group-cell rate coverage where per-observation coverage is degenerate.
- **Power-scaling sensitivity.** The classifier reproduces the ArviZ predicate comparison for comparison, reads the numeric columns (so the `✓`-means-clear encoding cannot mislead it), and writes atomically.
- **Release machinery, where wired, is deep.** The LRP-RLI-ITT-010 missingness gate reopens the trace, recomputes the convergence gate, matches every stored diagnostic at 1e-10, and binds the summary bytes by SHA-256. The floored-outcome six-cell prior grid gate (`sensitivity.py`) recomputes convergence and the effect summaries from content-addressed, provenance-embedded traces, and the producer script binds every cell to the primary fit's data digest and arm counts before sampling. The blending pair validator at build time is similarly thorough (two-way, config/data/seed/subject-order-matched; the paired ELPD standard error uses the correct paired formula).
- **Missingness bundle arithmetic.** The delta adjustments are declared in items and applied as `+delta/79` on the mean surface to the missing children only, per arm, clipped to [0, 1] with the clipped fraction audited; the sign convention and exact values were verified by algebra and against the fitted CSV. Jump-to-reference switches only the single intervention nonstarter to the control surface. The intercept prior is anchored to the all-57 screening word-reading mean and uses no outcome data.
- **Conventions.** The 89% equal-tailed interval is threaded from both constants with no reachable 0.95 fallback in the family (`tau_summary_itt` deliberately has no default); direction is read from the probability-scale average marginal effect with harm-aware favoured-direction labels; report suppression after a failed gate fails closed (unknown artefacts are withheld).
- **Registry.** All 38 modules declare typed settings; ids, kinds and outcomes match `definitions.MODEL_REGISTRY` exactly; none of the latent factory paths (varying tau, Gaussian processes, tau moderators, cross-baselines, sigma overrides) is used by any registered model.

## Findings

### 1. HIGH — the mandatory 008/108 blending pairing is invisible to `release_decision.json` (release-policy hole; no incorrect artefact currently published)

`release.evaluate_publication` has hard mandatory-companion branches for the ITT-010 missingness bundle, the mediation-t3 companions and the growth influence check — but nothing for the phoneme-blending pair. Verified on disk: both `lrp-rli-itt-008-reporting` and `lrp-rli-itt-108-reporting` carry `publishable: true, scientific_publication_eligible: true` with no pair check recorded. The registered policy is that neither result may be released without the validated trace-backed paired bundle; today that is enforced only in the key-findings builder (`reporting.py`, `_kf_blending_link_evidence`) and the copied report partial (`_results_itt.qmd`) — the same per-fit `_partials`-copy machinery that has gone stale before. Two aggravating factors: (a) the check-time evaluator `evaluate_local_blending_link_sensitivity` passes no-op trace validators, so the installed `blending_link_sensitivity.csv`'s own numeric effect columns are trusted as written — its hash columns bind the _other_ files (config, trace, the fifteen scientific artefacts of both fits), but nothing binds or recomputes the summary itself, in contrast to the missingness bundle's `summary_sha256` binding; and (b) the module docstring's claim that "the public-release check revalidates the central traces before publication" has no production caller. The fix is a blending-pair stage in `evaluate_publication` for the two registered B fits, mirroring the missingness gate, plus content-binding of the installed pair summary.

**Live counterpart discovered while fixing (2026-08-20).** The same evaluator had a relative-path bug with the opposite sign: the report partials call it with `Path(".")`, whose `.parent` is itself, so the sibling-fit lookup resolved to `<fit-dir>/lrp-rli-itt-108-reporting` and always failed at render time. The shipped `reporting` renders of 008/108 (rendered 2026-08-20 07:27, after the valid pair was installed) therefore carried "Findings withheld: response-link evidence is not current — [Errno 2] No such file or directory: 'lrp-rli-itt-108-reporting/config.json'" in the key-findings box and suppressed every scientific table, despite a passing gate badge and a valid pair. Fail-closed, so nothing wrong was published — but the shipped reports were wrongly empty of results.

### 2. MEDIUM — floor-rule fits release a `prior_data_conflict` verdict without the promised attenuation note

The documented policy is that a prior-data conflict releases with a note saying the reported size is a lower bound. The graded branch attaches `_PRIOR_ATTENUATION_NOTE`; `_floor_decision` returns a bare release once the six-cell grid is ready (or not required). Verified on disk: `lrp-rli-itt-009-reporting` has `robustness.tau_class = "prior_data_conflict"`, `status: ok`, and no note. The floored path demands more evidence than the graded path and then says less to the reader.

### 3. MEDIUM — the TROG-2 ceiling `n_trials = 32` had no recorded provenance and matches no standard form — RESOLVED same day: the value is correct

`measures.py` asserted "TROG-2: 8 blocks of 4 = 32 items" with `n_trials_confirmed=True`, but the claim dated to the first Bayesian commit (75639a0f) with no citation — unlike phonetic spelling (92), which cites Burgoyne et al. 2012, Table 3. TROG-2 is 20 blocks of 4 = 80 items, conventionally scored as blocks passed out of 20, and the repository's own Byrne-cohort note documents the original TROG the same way. The RLI data (observed maximum 27) rule out blocks-passed scoring but could not, alone, distinguish a short-form administration out of 32 from items-correct under a discontinuation rule out of 80 — and the denominator scales every probability- and items-scale effect for receptive grammar (LRP-RLI-ITT-026 and every other T-outcome family).

**Resolution (2026-08-20).** The trial's own paper settles it: the Methods section reads "Eight grammatical constructs were tested in blocks of four items; each correct item was awarded a score of 1", and the participant-characteristics table lists "Receptive grammar (32)" — Burgoyne, K., Duff, F. J., Clarke, P. J., Buckley, S., Snowling, M. J., & Hulme, C. (2012), Efficacy of a reading and language intervention for children with Down syndrome: a randomized controlled trial, _Journal of Child Psychology and Psychiatry_, 53(10), 1044–1053, <https://doi.org/10.1111/j.1469-7610.2012.02557.x>, archived in-repo at `papers/burgoyne-2012.md`. So the trial administered a short, item-scored TROG-2 form and `n_trials = 32` is correct; no refit is needed. The citation is now recorded in the `measures.py` comment so the provenance question cannot recur.

### 4. MEDIUM — `preprocessing._subset_prepared` does not subset `pre_counts` (latent misalignment)

`_subset_prepared` filters every per-row field except `pre_counts`, which `factories._subset` does handle, so the `PreparedData` returned by `restrict_to_baseline_floored` and `restrict_to_off_floor` carries full-length `pre_counts` arrays misaligned with every other array; it also leaves the dropped-row ledger untouched, so the floor-eligibility exclusions (53→41 for P, 53→36 for N) never appear in `dropped_by_reason`. No current consumer on the floor path reads `pre_counts`, and the count-drift `RuntimeError` in `pipelines/itt.py` protects the estimand, but the first future consumer inherits silently misaligned data. The fix is one line plus an alignment test so the two subset helpers cannot drift again. (The ledger question is left open deliberately: the floor restriction is a design/estimand restriction, not a data-quality drop, and it is already fully accounted in the eligibility tables and `config.json`; folding it into the loader ledger would change that artefact's meaning.)

### 5. MEDIUM (latent) — configuration traps, none live today

- **`target_accept` cannot be declared on the typed settings path.** `context.spec_target_accept` reads only `spec.extra`, but the typed ITT/joint boundaries raise on any non-empty `extra`, so the documented "model-specific default" precedence tier is unreachable for all 38 models, and the `_LEGACY_KEYS` comment in `itt.py` claiming a per-model declaration is accepted is wrong.
- **Legacy-versus-typed defaults diverge wholesale.** A minimal legacy `extra` declaration resolves to the retired cross-baseline LRP5x shape (all eight outcomes, seven cross-baselines, no linear age term), while the typed default is the uniform suite model. Nothing registered is affected, but re-materialising a spec from a bare dictionary silently flips the fitted model.
- **The APT outcomes (EI/EG/EI40) receive the proximal `tau ~ Normal(0, 0.5)` tier by omission** from `DISTAL_OUTCOMES`, with no recorded decision. EI's 80-trial denominator is the same scale-dependence argument that motivated the distal tier for R/E at 170 items. Possibly intentional (the locked DAG makes them direct outcomes of assignment); either way the tier judgement should be recorded.

### 6. LOW — smaller items

- `lrp_rli_itt_025.py`/`026.py` docstrings claim F/T have no agreed ROPE delta and that the meaningful-benefit table is omitted; both deltas have existed since 2026-07-20 and the table is published.
- String-truthiness in the blending archive validators (`bool(row["converged"]) is not True`, and the same idiom for `loo_reliable`) — safe today only because pandas parses clean boolean columns; quoted or mixed-case values would fail open (converged) or false-alarm (LOO reliability).
- `build_blending_link_sensitivity` overwrites the central archive manifest before running the release validation, so a failed rebuild clobbers the last good manifest (per-fit copies are installed after validation and stay consistent).
- The saved-CSV-versus-trace-recompute match in the blending bundle compares only the intersection of keys; a key rename in `reporting.py` would silently shrink the check.
- The jump-to-reference and delta rows label themselves `randomised_arm_factual_completion`, but observed children also contribute their posterior model-mean surface rather than their observed scores — identical in expectation under correct specification (the bundled posterior-predictive table is the guard), but the label does not hint at the model-standardised reading.
- The missingness provenance `coefficient_priors` record omits `tau` (`Normal(0, 0.5)`, correctly matched to the proximal primary) and `kappa` (`HalfNormal(50)`); `RLI_ARCHIVE_ZIP_SHA256` is recorded but never checked.
- A failed graded or hurdle secondary on the floor path flags but never blocks release — consistent with the registered policy (the release evidence is the grid), and the report suppresses non-converged secondaries, but it is the one required companion whose failure never reaches `release_decision.json`.
- A future B-outcome ITT model other than 008/108 would crash the key-findings builder with `KeyError('summary')` (`_kf_blending_link_evidence` assumes a `summary` key the not-required branch does not set).
- Per-parameter NaN R-hat/ESS values are skipped (`nanmax`/`nanmin`) rather than failing closed; BFMI, by contrast, fails closed on NaN.
- The sampling presets accept `--config rep`/`report` aliases that `_PUBLICATION_CONFIGS` does not, so such a fit pays reporting-scale sampling yet is permanently `development_only` (fail-closed, but an expensive trap).
- `rope_summary`'s probability of direction is coefficient-based for ITT while `tau_summary`'s headline direction is AME-based — provably identical for every registered model (monotone links, no moderators), but they would diverge if a varying-tau or moderated ITT model were registered; the gain family already handles this with `direction_from_ame=True`.
- Assorted stale prose: `003`/`004` "ceiling unconfirmed" (confirmed since #214), `016`'s `b1rectau` column name (it is `b1retau`), `itt_audit.randomised_postscore_bounds`' docstring describing fitted-set bounds when production deliberately recomputes trial-wide bounds (the better estimand), and `spec.adjustment` hand-duplicating `model_settings.adjust_for` with no validator.

## Test-coverage gaps

The blending bundle's trace-recomputation core is never executed in tests (`_load_fit_record` is monkey-patched away, and the negative paths of `_validate_archive_trace`/`_validate_archive_row_map` are untested); `_reconcile_included_rows`, `run_missingness_subfit` and `missingness_ppc_summary` in the missingness module are untested; and there was no test pinning `_subset_prepared` against `factories._subset` (finding 4 would have been caught by one).
