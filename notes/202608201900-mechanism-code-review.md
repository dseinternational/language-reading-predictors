## Finding 1 (statistical/reporting, moderate): mech-191's analysis population is misdescribed — the fit includes the zero-dose waitlist rows its own report says were dropped

The module docstring (`lrp_rli_mech_191.py`) and the published report (`docs/models/lrp-rli-mech-191/index.qmd`, lines 36–38) state that `attend` "has 55 missing values (the pre-/no-intervention rows, where a per-period session count is undefined); these survive as NaN and are dropped by the factory's exposure keep-mask, so the fit uses exactly the on-intervention rows that actually carry a dose." That is not what the data contain or what the fit does:

- In the long CSV, `attend` is missing on **54 rows at t4 and 1 row at t2** — that is the "55". But t4 never supplies a pre row in the all-transitions frame (pre rows are t1/t2/t3), so at most one of those 55 cells can ever reach this model.
- Waitlist children's period-1 sessions are recorded as **0, not NaN** (all 26 waitlist t1 rows have `attend = 0`). Rebuilding the fitted frame reproduces the stored run exactly: 156 rows, 53 children — the same frame as mech-058 — of which **28 rows have zero recorded sessions** and only **7 rows lie between 1 and 30 sessions**. The fitted exposure percentiles are 0 (min), 0 (10th), 33.8 (25th), 65 (median), 78.2 (75th), 94 (max).
- The published artefacts already embody the zero-anchored population the prose denies: `readiness_threshold.csv` has `obs_count_min = 0`; `mechanism_summary.csv` runs its endpoint contrast from **0 to 94 sessions** (+2.2 words, 89% interval +0.2 to +4.2, probability of a positive difference 97%); and `key_findings.json` leads with "Across the fitted exposure range (0 to 94 attend raw-score units)…". The same report therefore claims an on-intervention-only population three paragraphs above a headline anchored at zero dose.

The statistical consequence is not cosmetic. At period 1, dose is nearly deterministic in arm (every waitlist child at 0; immediate-arm median 75), so the left end of the HSGP curve is largely the between-arm contrast that `beta_G` also carries, and the stretch from 0 to ~30 sessions is interpolation over 7 rows. The published knee (median ≈ 40 sessions, 89% interval ≈ 40 to 75 — the lower limit coinciding with the median, which suggests the binned-knee posterior is concentrated on a single quantile-bin interval shaped by the mass at zero) should not be read as "sessions beyond ~40 begin to pay off among treated periods" until the population question is settled.

**Recommendation.** Decide the population and make the prose and the fit agree. Either (i) keep the zero-anchored all-transitions population — which is the established dose-response design (dose-077 explicitly wants the waitlist zero-dose anchor) — correct the module docstring and the report lines, move the key-findings headline onto the interquartile worked example the items writer already computes (33.75 → 78.25 sessions, +1.2 words, 89% interval +0.0 to +2.5), and add the support-gap / period-1 dose-equals-arm caveat beside the knee; or (ii) restrict the fit to on-intervention rows as the prose intends, which needs a spec-level restriction the family does not currently expose, and refit. Option (i) is smaller and consistent with the family's own cross-references.

## Finding 2 (comparator validity, moderate): mech-158 is no longer "identical to LRP58 in every respect except" the complete-case restriction

mech-158's whole role is stated in its docstring: identical to mech-058 except that the mean-imputed confounder rows are dropped, so any slope difference isolates the imputation policy. Two divergences have crept in:

- **Functional form.** When #438 reparameterised mech-058's curve (`mech_hsgp_m = 6`, `mech_lengthscale_tight` → InverseGamma(8, 8)), mech-158 was not updated: its stored reporting run confirms it still fits the shared defaults (basis 10, lengthscale InverseGamma(5, 5)). The 058-vs-158 comparison now varies the basis count and lengthscale prior alongside the imputation policy. The #438 note measured the lever's effect on 058 as small (curve amplitude +1.5 to +2.9%, pointwise change < 0.02), so the numbers are probably still comparable — but "identical in every respect except" is the claim the comparator's read rests on, and it is currently false in the estimand's own functional form. (mech-158 passes its gate cleanly at the defaults — max R-hat 1.003, min ESS ≈ 3700 — so this is about the claim, not convergence.)
- **Analysis-population spec.** mech-158 omits `outcomes`, so its resolved plan is the family default: `pre_required` = all eight ITT outcomes (W, R, E, L, P, B, F, T) and at-least-one-post over all eight, versus mech-058's declared (W, L). I verified empirically that on the current CSV this costs nothing: the complete-case children happen to be complete on all eight pre-scores, so the loader returns the identical 129-row / 44-child frame under either declaration (128 rows after the W/L post keep-mask, matching the stored fit). But the equality is a coincidence of the current data, not a property the spec enforces — a future data revision could silently move the comparator onto a different row set from the model it exists to check.

**Recommendation.** Declare `outcomes=("W", "L")`, `mech_hsgp_m=6` and `mech_lengthscale_tight=True` on mech-158, refresh the stale "Matches LRP58" paragraph, and refit it in the next batch — or record a dated decision that the comparator deliberately keeps the shared defaults, and weaken the "identical in every respect" sentence accordingly.

## Finding 3 (functional, latent): the `outcomes=None` branch skips the required-measures coverage validation

When a spec declares `outcomes`, `resolve_mechanism_run_plan` checks that every bounded model term — the outcome, a measure exposure, the autoregressive baseline, measure confounders and a measure moderator — is contained in it. When `outcomes` is omitted, the loader falls back to `ITT_OUTCOMES` and **no coverage check runs**. A spec whose baseline or exposure is a bounded measure outside that set (TR, TE, N, …, none of which are in `ITT_OUTCOMES`) would resolve a "validated" plan, reset the output staging directory, load the data, and only then die with a `KeyError` in the factory — exactly the late-failure class the pre-I/O boundary (#394 pillar 4) exists to prevent. No registered spec is affected (only mech-158 omits `outcomes`, and W/L are in the default set), so this is latent. Fix: in the `outcomes is None` branch, run the same required-measures check against `ITT_OUTCOMES`.

## Finding 4 (convention, minor): the cross-model mechanism forest reports posterior means, and its curve slope averages over unique grid values

`scripts/compare_statistical_models.py::mechanism_forest` plots `slope_mean` (the posterior mean) with an 89% equal-tailed band — the suite's median-first convention (#271) is not applied. Separately, `_mechanism_slope_distribution` averages `np.gradient` over the deduplicated sorted grid of observed logits, which weights the curve's slope by where distinct observed values happen to sit rather than by data density (a fitted-population average derivative) or the end-to-end secant; for a linear fit the definitions coincide, for the mech-058 curve they need not. Neither affects any per-model artefact. Fix: use the median for the point estimate, and either document the unique-grid weighting in the CSV or switch to a per-draw density-weighted mean derivative.

## Finding 5 (audit record, minor): a moderated fit's conditioning on the moderator is absent from `effective_adjustment`

The factory's own docstring notes that `gamma_mod` "also serves as the adjustment for M when M is a DAG confounder", yet the fitted-adjustment record in `config.json` (`adjustment.py::effective_adjustment`) lists only the measure confounders, `adjust_for` covariates and the autoregressive baseline; the moderator surfaces elsewhere (`extra.moderator_symbol`, `interaction_summary.csv`). An auditor reconstructing the conditioning set from `effective_adjustment` alone would omit the moderator's main effect (and interaction) for the thirteen moderated fits, including the main-effect-only companions. Fix: append a `moderator_main_effect` term (and, when fitted, `moderator_interaction`) to the record.

## Finding 6 (headline construction, minor): the family's `mechanism_summary` contrast compares the two most extreme observed rows

`_write_mechanism_curve` builds the items-scale end-to-end contrast between the single lowest and single highest observed exposure values, and `_kf_build_mechanism` builds the key-findings headline from it. Extremes of a 128–156-row exposure distribution are noisy anchors, and in mech-191 the minimum is the other arm's no-dose period (finding 1). The items-scale companion already computes an interquartile worked example with a computed caption. Fix: prefer the quantile contrast for the headline sentence (or state the endpoints' sample ranks alongside), keeping the full-range contrast as a secondary line.

## Observations (no action required)

- mech-104/204 keep the shared HSGP defaults (basis 10, InverseGamma(5, 5)) and the preset `target_accept` while every other letter-sound-to-word-reading curve fit carries the thin-support reparameterisation plus 0.999; both pass the gate cleanly on their smaller complete-case row set (max R-hat ≤ 1.003, min ESS ≥ 2300), so nothing is wrong — a line in the mech-104 docstring recording that the defaults suffice there would stop it reading as an oversight.
- `alpha` plus a free `alpha_phase ~ Normal(0, 0.5)` is a translation-ridge parameterisation (the level-factors family removed its analogous ridge with a zero-sum constraint in #389); with three phases and these priors every mechanism fit samples cleanly, so this is efficiency headroom, not an error.
- mech-090's docstring says the linear mechanism is "required for a covariate exposure"; since the covariate-HSGP path shipped (mech-191), that is a choice, not a constraint.
- `fit_mechanism` carries an orphaned comment about honouring `target_accept` whose implementation moved to `context._resolve_target_accept`; the precedence itself is correct and centrally applied.
- The nonword (N) outcome fits are graded Beta-Binomial without the suite floor rule — an explicitly documented decision (mech-072/096/102/103: the graded count is the right leg for an exposure-association slope; the floor rule protects treatment marginals), with the power caveat carried in the module docstrings.
- No registered spec uses `mechanism_at_pre` or `phase_specific_mechanism`; both paths are guarded (the curve writer warns rather than silently skipping on a phase-specific fit, and the exact-refit machinery refuses phase-specific bases it cannot pin).

## Verified sound (checked, no issue)

- **Pre-I/O plan discipline.** Unknown setting keys, mixed typed/legacy declarations, misshaped values and cross-field contradictions (linear mechanism with HSGP settings or phase-specific curves, a covariate exposure or moderator also in `adjust_for`, bounded measures in raw-covariate roles, a mis-declared autoregressive baseline, filled covariates without an indicator or complete-case policy) all fail before `make_context` resets the staging directory or any data load; a stale attached plan is rejected by exact reconstruction (`validate_mechanism_run_plan`). All pinned by tests, including an ordering test that asserts neither context creation nor loading runs on an invalid spec.
- **Row alignment.** `attach_built` swaps `ctx.prepared` to the factory-subset frame, so the mechanism curve, items curve, readiness threshold, moderation cells and per-child panels are computed on the fitted rows; the moderation-items writer additionally proves row identity by requiring an exact affine map from re-derived natural-unit values onto the stored standardised vectors, and refuses on any drift; the cross-model forest reads the persisted `mech_post_logit` rather than reconstructing it (the 2026-08-05 fix).
- **Keep-mask completeness.** Outcome and exposure post-scores, measure-moderator and measure-confounder post-scores and all adjuster covariates are masked in the factory; period-start scores are guaranteed by the loader's `pre_required` (validated to cover the baseline and any at-pre exposure whenever `outcomes` is declared — finding 3 covers the `None` branch); loader-filled covariates are NaN-free by construction, and covariate moderators/exposures are forced through `require_observed`.
- **Standardisation and the frozen design.** The exposure and moderator are re-standardised on the kept rows, so per-SD readings match the fitted data; the HSGP input is the standardised logit with its boundary derived from the same vector; the realised scalers and boundary are pinned in `MechanismPayload` and replayed into exact-LOO refits so a refit's basis weights are defined against the fit's design.
- **Exact-LOO refits (`loo_refit.py`).** Refuses multi-observed models, derives the observed-node name from the built model and verifies it against the stored trace, reproduces the stored log-likelihood **and** log-prior to 1e-6 before any refit (failing closed when `log_prior` is absent), refuses to hold out a child's only row, requires the refit frame to be exactly one row fewer with an unchanged child dimension, and re-gates every refit on unrounded R-hat/ESS/BFMI and zero divergences.
- **Items-scale curve algebra.** The per-draw reference constant removes the mechanism, child-intercept and moderator contributions exactly (unit-tested to 1e-9 across the GP/linear, child and moderator combinations); the worked example interpolates strictly within observed support; the prior pushforward pushes the prior group through the identical transform, so the prior check is a check of the reported quantity.
- **Interaction machinery.** `gamma_mod`/`gamma_int` have fixed names that cannot collide with the confounder loop; age-as-moderator suppresses the collinear linear age term, and a represented-confounder invariant fails loudly if any declared confounder never reaches the linear predictor; the no-interaction companions differ by exactly `gamma_int` with identical priors on the shared terms (the #270 prior-invariant nesting).
- **Transforms and the gate.** Haldane-corrected logit inversions use the (n + 1) denominator everywhere (curve endpoints, knee back-transform); the convergence gate scans all free random variables (HSGP weights and hyperparameters included) combined with the curated terms; the power-scaling variable names `f_mech__eta`/`f_mech__ell` exist on every registered curve fit and are correctly omitted for linear fits.
- **Priors.** `beta_G` deliberately keeps the proximal Normal(0, 0.5) scale for every outcome (documented: outcome tiering applies to randomised terms only, and mechanism `beta_G` is an adjusted-association nuisance); `alpha` is tiered by outcome; the mechanism lengthscale priors and the thin-support opt-in are scoped per model with the shared defaults untouched.
- **Covariate timing.** State confounders (hearing, speech, phonological memory) are read contemporaneously from the post row and sessions from the pre row (`INTERVAL_COVARIATES`), per the #258 review; the gain-/level-factor baseline-timing split is deliberately not applied to this avowedly associational family (`split_confounders_by_timing` docstring records why).
- **Loader fail-loud checks.** Duplicate (subject, time) keys, within-subject randomised-group changes, fractional/negative/above-ceiling counts, and constant-covariate dropping reconciled into `effective_adjustment`'s `dropped_constant`.
