# One artefact interface, a fit-level manifest, and the shared primary-fit lifecycle (#394, tranches 1–3)

**Date:** 2026-08-07. **Issue:** #394 (complete the statistical pipeline family split and artefact lifecycle refactor), implementation-sequence steps 2–4. **Change:** behaviour-preserving throughout.

## Tranche 1 — the artefact interface and manifest (steps 2–3)

`pipeline.py` wrote every published table with an inline `df.to_csv(os.path.join(ctx.output_dir, ...))` followed by a manual `ctx.tables[...]` registration — 109 write sites and 104 registrations at the time of the #394 review — and guarded optional artefacts with ad-hoc `except Exception` blocks that printed a one-line warning and recorded nothing. Nothing stated which artefacts a fit produced, which optional ones were skipped, or why; the #394 review flagged exactly this ("without a common structured record of skipped artefacts").

`statistical_models/artifacts.py` now provides:

- **`save_table(ctx, name, df, *, filename=None, required_columns=None, index=False, register=True, required=True)`** — one operation that writes the CSV into the fit's output directory, registers the frame on `ctx.tables`, optionally validates required columns (fail-loud, before anything is written), and records the artefact. The historical three-line idiom becomes one line, and the write and the registration can no longer drift apart.
- **`guard_optional(ctx, label, *, filename, kind, verb)`** — the warn-and-continue guard as a context manager: an optional artefact's failure still prints the same `[yellow]{label} {verb}: {exc}[/yellow]` warning and never aborts an expensive fit, but the failure type and message are now persisted instead of scrolling away. `verb` reproduces each historical guard's own wording ("skipped", "failed", "not written") so every converted site stays message-identical. Only `Exception` is caught, exactly as the guards it replaces.
- **`record_artifact(ctx, name, *, filename, kind, required, df)`** — records an artefact written by a writer this interface deliberately does not own (see tranche 2), so the manifest reports it as `written` instead of `untracked`.
- **`write_manifest(ctx)`** — called by the shared `SharedFitStages.finalize_report` after the report-template copy and before publication, so every family gets `artifact_manifest.json` in its output directory with no per-family wiring. The manifest reconciles the fit's artefact log with a recursive directory scan: recorded artefacts carry status (`written` / `skipped`), shape (`n_rows`, `columns`) and any skip reason (`error_type`, `error`); files present on disk but not routed through the interface appear as `untracked` with a kind inferred from the extension; an untracked CSV sharing a stem with a `.png`/`.svg` is classified `figure_data` (a `save_styled_figure(data=...)` sidecar, not a not-yet-migrated table); a recorded write whose file has vanished is surfaced as `missing` rather than silently dropped.

`StatisticalFitContext` gains an `artifacts: ArtifactLog` field (default-constructed, so no call-site changes), and the interface duck-types the context — `getattr` fallbacks for `tables` / `artifacts` — so the lightweight namespace contexts used by sweep runners and tests keep working.

All 109 `to_csv` sites in `pipeline.py` were migrated (94 by a shape-checked mechanical transform that collapses only exact adjacent write+register pairs with matching frame expressions; the rest by hand: the deliberately unregistered writes — `analysis_rows.csv`, `proportion_at_zero_ppc.csv`, `readiness_threshold.csv`, the historical-joint per-measure loop — which pass `register=False`, the concurrent loop, and the mediation blocks whose registrations sat apart from their writes).

### Why the manifest scans the directory

Adoption is incremental (this is #394's point: extract helpers first, then move families). If the manifest listed only interface-routed artefacts it would be an inventory of the migration, not of the fit. The reconciliation scan makes it a complete inventory of the fit directory from the first adoption, and the recorded/untracked split doubles as the adoption metric.

## Tranche 2 — completing step 3: the remaining guards and the module-tail writers

- **Every warn-and-continue guard in `pipeline.py` is now `guard_optional`** — the four table guards from tranche 1 plus the ~20 figure-emitter and pushforward guards (converted by a script keyed on each guard's exact `(label, verb)` message pair, so wording is proven preserved; the dynamic-label sites — the PPC overlay's `filename_stem`, the forest plot's `{name}` — by hand). The handlers deliberately kept are the ones whose `except` does real work: the "absence must stay legible" fallback-row builders, the produce-only guards where a save failure was fatal before and stays fatal (`indicator_prior_check`, the level-factors pushforward), the mechanism items-curve handler (its `except` writes the unavailable-pushforward), a cosmetic label fallback, and the structured failure recorder.
- **Module-tail table writers migrated**: `itt.py`'s analysis audits (`analysis_set.csv`, `attrition_bounds.csv`, the PPC calibration pair) and `diagnostics.py`'s `diagnostics.csv` / `diagnostics_deterministics.csv` now go through `save_table` (the matrix-style ones with `index=True`).
- **Boundary recording where the write mechanics are deliberately owned elsewhere**: `psense_summary.csv` keeps its atomic temp-and-rename writer (shared verbatim with `scripts/regenerate_psense.py` — one implementation, no drift) and is recorded by the fit-time wrapper `run_psense`; `predicted_scores.csv` and `mechanism_curve_items.csv` are written by helpers that take an output directory rather than a context, and are recorded at their pipeline call sites; `trace.nc` is recorded by `save_trace` (kind `netcdf`). The post-hoc sweep/attach writers (`sensitivity.py`, `blending_sensitivity.py`, `influence.py`'s bundle index) are not fit-time artefacts — the manifest is a fit-time record — and keep their atomic writers untouched.

**Result, verified on the six dev fits below: no fit manifest contains any untracked `table`-kind CSV.** The untracked set is now figures, `figure_data` sidecars, JSON written by shared `dse_research_utils` writers, and the report-template copy.

## Tranche 3 — step 4: the shared primary-fit lifecycle and its reference family

The #394 review's structural finding was that 26 primary branches independently spell out the prior-predictive → sampling → LOO → diagnostics → posterior-predictive → gate → trace sequence. `stages.py` now owns it:

- **`PrimaryFitPlan`** — a frozen value object holding the genuinely variable execution choices the issue enumerates: curated `diagnostic_vars`, `ppc_var_names` (last = primary node), `prior_predictive_draws`, the family's `plot_prior_predictive` hook, `psense_vars` (defaulting to the diagnostic set), the `extended_term` the rank/ESS plots focus on (`None` skips the extended block; the all-free-variable gate still runs), and the `include_loo_pit` / `compute_loo` / `save_trace` policy. Deliberately a flat declaration, not a base class with overridable methods — a reader sees a family's whole execution profile in one literal.
- **`SharedFitStages.run_primary_fit(ctx, plan)`** — the invariant sequence, expressed once, with two ordering tests in `tests/statistical_models/test_stages.py` pinning the full event order and the genuine family differences (no-LOO, no extended term, distinct psense vars, no trace save).
- **`fit_survival` is the reference adoption**: its hand-sequenced mid-section is now one `run_primary_fit` call with a five-line plan; preparation, model build, the hazard summary, metadata and finalisation stay explicit. Byte-identical artefacts verified below. Remaining families migrate in later tranches as they move into family-owned pipeline modules (steps 5–6).
