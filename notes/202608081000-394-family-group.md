# The first family group moves: DiD, factors, aligned, block exposure and dose-response (#394, tranche 5)

**Date:** 2026-08-08. **Issue:** #394 (complete the statistical pipeline family split and artefact lifecycle refactor), implementation-sequence step 6, first group. **Change:** pure relocation — no estimand, likelihood, prior, analysis population, fitted equation, sampling preset, diagnostic threshold or artefact schema is touched.

## What this tranche does

Six more families leave the monolith: `fit_did`, `fit_gain_factors`, `fit_level_factors`, `fit_aligned`, `fit_block_exposure` and `fit_dose_response` now live in `statistical_models/pipelines/`, joining `itt` and `joint` from [tranche 4](202608072330-394-pipelines-family-split.md). `pipeline.py` drops from 7,483 lines to 5,609 — down from 10,182 two tranches ago. Eight of the twenty-five family entry points are now family-owned, and `pipeline.py` re-exports all eight, so no model module or test changed its import path.

## Why dose-response joined the group

The issue's first group is "DiD/factors/aligned/block exposure"; dose-response belongs to the second. Taking the first group alone would have left three helpers stranded between the moved families and the monolith — `_effective_adjustment` (125 lines), `_summarise_draws` (23) and `_write_dose_slope_summary` (110) — each needing a shared home. Two of those three are dose-slope machinery shared by exactly two families: the DiD dose companions and the dose-response family, which publish the same per-period slope table. Splitting them would have meant inventing a shared module for a two-consumer helper.

Adding `fit_dose_response` to the group collapses the stranded set from four helpers (270 lines) to two (137), for 231 extra lines of relocation. The dose helpers become group-internal, and `pipelines/did.py` imports `write_dose_slope_summary` from `pipelines/dose_response.py` — the sibling-import pattern already established when `joint` took the ITT audits from `itt`.

## The two helpers that needed homes below the split

- **`default_of`** → `factories.py`. Nine families use it to read a prior-scale default straight off the factory signature rather than re-typing the number (#209 review). Eight of them stay in `pipeline.py` for now, so it had to move below. `factories.py` is the honest home: the function is _about_ a factory's signature, and putting it there makes the anti-drift device live next to the thing it guards.
- **`effective_adjustment`** → new `adjustment.py`. It builds the `config.json` record naming, for every term that carries a coefficient, its source column, wave and missingness role — plus the requested-but-dropped terms. Used by the two factor families (moving) and the mechanism family (staying). `provenance.py` was the tempting existing home but is about _run_ provenance — git, packages, platform — not about what a model conditioned on, so a small dedicated module is the honest split.

## The relocation, checked the same way

Same discipline as tranche 4, and it caught nothing this time because the partition was already clean: the AST reachability scan confirmed **no function in the moved set references anything that stays in `pipeline.py`**, and the move script's region tripwires (expected opening line, AST statement-boundary end, blank separator, no overlap) all held on the first run.

Only three names crossed a module boundary and were promoted — `default_of`, `effective_adjustment`, `write_dose_slope_summary`. Every family-private helper (`_did_diag_vars`, `_gf_coef_names`, `_al_coef_names`, `_summarise_draws`, …) kept its name inside its new module.

Verification of the relocation itself:

- **Byte-identity.** Re-applying the three-name rename map to the original line ranges reproduces the eight new files exactly — **8 of 8 regions byte-for-byte**, with no exceptions this time.
- **No string was renamed.** Tokenising the pre-move `pipeline.py` and searching only `STRING` tokens for the three old names returns **zero** hits, so no artefact filename, table key, console label or guard message could have been touched.

One thing worth recording because it nearly went wrong: the first pass of the import clean-up used `str.count(...)` on a bare `from … import MEASURES` line, which matches the _indented_ function-local imports too, and aborted on an assertion. Anchoring the pattern at column 0 fixed it. The assertion did its job — a silent `replace` would have deleted a deliberate lazy import inside a function.
