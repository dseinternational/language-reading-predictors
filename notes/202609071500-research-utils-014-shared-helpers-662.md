# Research utilities 0.14.0: adopting the shared helpers

[Issue #662](https://github.com/dseinternational/language-reading-predictors/issues/662) moves the `dse-research-utils` pin to tag `v0.14.0`, which resolves to commit `50390f4f9cd19033e3d0dc9bd050b383bd413c36`, and routes this repository's remaining copies of the consolidated helpers through the library. The extras and the shared dependency floors are unchanged, and `uv sync --locked` installed that commit. The contracts are described in the [0.14.0 upgrade notes](https://github.com/dseinternational/research/blob/v0.14.0/docs/migrating-to-0.14.md) and the [combined migration guide](https://github.com/dseinternational/research/blob/v0.14.0/docs/consolidation-migration.md).

This note records what was delegated, what was deliberately kept, the four places the behaviour is now stricter than it was, and the evidence that no model needs refitting because of it. The separate [0.13.0 work](202609061600-research-utils-013-upgrade-660.md) — including the 20 pending HSGP reporting refits — is unchanged by this upgrade and remains open under [#660](https://github.com/dseinternational/language-reading-predictors/issues/660).

## What each adapter delegates, and what it keeps

**Files.** `storage.files.atomic_write` now creates the temporary file, performs the single rename and cleans up after a failure for the psense summary, the blending-archive install and CSV, the influence bundle index and copy, and the historical-growth influence artefacts. Every caller still writes its own bytes, so CSV/JSON encoding, index handling and trailing newlines are untouched. The one thing the library cannot decide is the _published file mode_: its temporary file is `mkstemp`'s owner-only `0600`, and two of these writers previously created their temporary file with a plain `open` and therefore published at the process umask, usually `0644`. `atomic_files.write_atomic` takes an explicit mode policy for exactly that, probing the directory rather than reading `os.umask` (which can only be read by setting it, process-wide). The content-addressed installs whose _destination name_ comes from the staged file's digest — the influence trace and `persist_sensitivity_trace` — cannot be expressed through a fixed-destination helper and stay local.

**Directory promotion.** `OutputTransaction.publish` hands its two renames, its backup-first ordering and its restore-on-failure attempt to `storage.directories.promote_directory`. The class keeps the staging directory and its mode, the private backup _name_, backup retention and the stale-sibling cleanup — the helper deletes nothing — and passes a null context as its lock, which is what the library documents for a single writer with exclusive access to those paths. That is what this process already had: a private `mkdtemp` staging tree and one model's own output directory.

**Provenance.** `source_provenance` keeps its four manifest field names, their order and the `None`-when-unknown convention, but the facts behind `commit` / `branch` / `dirty` now come from one bounded `git status --porcelain=v2` through `metadata.provenance.git_snapshot` instead of three separate Git invocations. `repository_root` has no shared equivalent — the snapshot deliberately returns no filesystem paths — so it keeps its own `rev-parse --show-toplevel`, which is also what still decides "not a usable checkout". The package-version lookup delegates but stays behind this project's process-lifetime cache, because a fit's manifest must describe one environment rather than re-query it per artefact. Five separate copies of the same 1 MiB-chunk file digest — in `influence`, `sensitivity`, `run_metadata`, `subfits` and `provenance` — now call `metadata.provenance.sha256_file`; the `sha256:` prefixes and digest-prefix filenames built on top of it are unchanged.

**Predictive arrays.** `_ppc_node_arrays` builds its observation-by-sample matrix with `statistics.samples.sample_matrix` and checks the observed vector with `SampleMatrix.observed_values`; the coverage, calibration and off-floor tables get their bounds, medians and inclusion flags from `statistics.predictive.predictive_observation_checks`. The non-finite observation mask, the group cells, the closed-interval convention and every column name stay in this module, as does the zero-observation result — a fit with no finite observed row still writes its coverage row with `n_total = 0` and `coverage = NaN`, which the shared helper refuses to produce because it rejects an empty observation axis.

**Child-level likelihood.** `_joint_log_likelihood_by_child` hands its row-to-unit sum to `statistics.log_likelihood.aggregate_log_likelihood`. Everything that decides _what a unit is_ stays here: which constant map names a child, which likelihood node that map belongs to, how many children there are, and the refusal of an out-of-range index.

**Feature groups.** The distance-correlation tree and its cut now come from `ml.feature_groups.linkage_from_dissimilarity` and `feature_groups_from_linkage`, in `cluster_ranking.average_linkage_tree` / `cluster_ids_by_feature` / `cluster_table`, shared by the per-fit diagnostics and by `scripts/rank_predictors.py`'s cut-height sensitivity. The `cluster_id` column keeps SciPy's own numeric labels — `cluster_table.csv`, `importance_pairing.csv` and the cluster-importance tables all join on them — and keeps its `int32` dtype, which building the column from Python integers would silently widen to `int64`.

**Permutation.** `pooled_permutation_deltas` keeps this project's donor design in full: one subject-block permutation per repeat, drawn from `default_rng([seed, r])`, with the recipient's rows aligned to the donor's and wrapped when the donor has fewer, and the _same_ plan handed to every block so block iteration order cannot move a delta. The baseline, the permuted frames, the pooled out-of-fold score and the delta sign are `ml.permutation.pooled_oof_permutation_deltas`. The score remains pooled RMSE over every held-out row at once, never an average of fold scores: with near leave-one-subject-out folds a fold score is one child's error, and averaging would weight a one-row child like a four-row one.

**HSGP geometry.** The mechanism factory expresses its frozen basis through `statistics.models.hsgp_design.HSGPDesign` — `from_domain` for a fresh fit, the saved scalars replayed for a refit — and `MechanismDesign` validates a stored design through the same type. The graph is still built by this project's `build_hsgp_1d` wrapper with explicit `m` / `L` / `center`, so the priors, variable names, dimensions and the fitted projection are untouched. `HSGPDesign.from_domain` performs the same arithmetic the factory did inline (half the input range about the input midpoint, expanded by `c`), and adds PyMC's own checks that the resulting basis stays representable in float64 on top of it.

**Report reads.** `_setup.qmd`, `_gate_badge.qmd` and the research report's `_report_data.qmd` read through `report.readers`. The diagnostic-column allowlist, the unknown-file fail-closed rule and the _ordering_ — visibility is decided before a file is opened, so a withheld scientific table is never parsed — are unchanged, as is the late withholding `_key_findings.qmd` relies on: `_csv` and `_img` read the module-level released flag when they are called rather than capturing it.

## Where the behaviour is deliberately stricter

1. **An unreadable artefact is no longer indistinguishable from an unfitted model.** `_json` / `_csv` and the report's `load_summary` / `load_diagnostics` returned `None` both for a missing file and for a corrupt one, so a truncated or half-written artefact rendered as the reassuring "pending fit" placeholder. A present-but-unparsable file is now recorded, named in the report, and withholds the results that depend on it. The shared JSON reader is also stricter than `json.load`: bare `NaN` and `Infinity` tokens are not JSON and are refused rather than read back as floats. No stored artefact is affected — all 1,717 JSON files under `output/statistical_models/models/` parse cleanly under the strict reader.
2. **Observed values must identify the replicated rows.** The retired reshape checked only that the two arrays had the same number of rows; `SampleMatrix.observed_values` compares coordinate labels. A misaligned observed vector produced a plausible coverage number, which is the worst kind of wrong. Every stored `trace.nc` carries explicit coordinate indexes on every dimension, as PyMC and ArviZ always write, so this rejects nothing real; the synthetic trace fixtures in the test suite were updated to label their axes the way a real trace does.
3. **A child with no likelihood row is refused rather than scored as zero.** The `y_post_cell_row` branch took its unit count from `G`, so a declared child with no observed cell would have been appended to the PSIS-LOO as a silent zero-likelihood unit — the phantom-unit defect the `loo_child_idx` branch was already guarded against. That now raises.
4. **The derived-estimand gate recomputes `passed` from the merged checks** rather than only forcing it to `False` on failure, and writes through `diagnostics.amend_diagnostics_summary`. The two agree on every reachable case, but the amendment is now atomic, its per-quantity detail rows are sanitised (a missing ESS or MCSE used to be written as a bare `NaN` token, which is not valid JSON), and `ctx.tables["diagnostics_summary"]` now agrees with the file. That last point also fixes a latent inconsistency in `reclassify_structural_constants`, which rewrote the file after a verdict change but left the fit's cached table holding the pre-reclassification verdict.

One arithmetic convention changed without changing a result: the shared predictive helper takes its upper bound at `1 - (1 - p) / 2` where this module used `(1 + p) / 2`. The two are algebraically equal and identical in float64 for every `p >= 0.25`, which covers every interval this project publishes (50%, 89%, 90%, 95%). A test pins that agreement so a future narrower reporting width fails there first rather than silently moving an endpoint inclusion.

## Rechecks that did not result in an adoption

`statistics.loo.pareto_k_reliability` reduces a pointwise Pareto-k array to a scalar record. This repository's two consumers are not scalar reductions: `write_loo_influence` and `growth_pareto_table` publish a _per-row_ `loo_reliable` column beside each observation's k, and `influence_diagnostics` counts a non-finite k as flagged, which the shared `n_above` (a literal threshold exceedance, on which `NaN > k` is false) deliberately does not. The blending archive's `pareto_k_max` and `loo_reliable` are a frozen schema whose stored values are key-matched on read, and `np.max` on an empty array raises where the shared reduction returns `NaN`, which would turn a degenerate fit into a recorded null. These are kept local.

`statistics.array_intervals.equal_tail_interval` has no local implementation to replace: the remaining `np.quantile(..., axis=1)` calls are two-line steps inside table builders that each own their column names, and this project is not listed for that helper in the migration guide's per-consumer table. `report.assets` likewise has no counterpart here — this repository has no local HTML asset scanner; `scripts/upload.py` already consumes the structured `BlobUploadResult` from the 0.13.0 work.

## No refit is required by this upgrade

`model_design_identity` was recomputed for all 46 registered mechanism models — the family whose construction path this change touches — under three combinations: `main` with 0.13.0, `main` with 0.14.0, and this branch with 0.14.0. **All three agree exactly on every model**, both `structure_sha256` and `design_sha256`. Neither the library bump nor the adapters move a computational graph, so no fit needs resampling on account of #662.

The same recomputation against the 47 stored mechanism `config.json` files disagrees for every one of them — but it disagrees identically on `main` at 0.13.0, so that gap predates this branch and belongs to the refits already pending under #660. Stored artefacts are untouched, and their manifests are preserved as records of their actual producers.

`environment_lock_sha256` does change, because the installed distribution set changed. Trace reuse against a fit published before this upgrade is therefore refused by the reuse contract, which is the intended reading of an environment change rather than a defect.

## Validation

- `uv sync --locked` installed `dse-research-utils` 0.14.0 at the released commit; installed metadata confirms both.
- **Old-versus-new numerical agreement, on real artefacts, not fixtures.** Over all 286 stored reporting traces and 329 predictive nodes, the retired and delegated implementations of `_ppc_node_arrays`, `ppc_interval_coverage`, `ppc_calibration_table` and `ppc_offfloor_cell_table` produce identical arrays and identical complete tables, including the grouped and ungrouped off-floor cases. Over the 29 traces carrying a child map, the retired and delegated child aggregates are identical arrays with identical coordinates, name and attributes. Clustering agrees on 300 random dissimilarity matrices — tree, labels, table row order and `int32` dtype — and pooled permutation deltas agree bit-for-bit on six synthetic longitudinal cohorts including a child-constant predictor and a multi-column cluster block. `HSGPDesign.from_domain` reproduces the retired boundary arithmetic exactly on 2,000 random domains. `source_provenance` returns the same four fields as the retired three-command implementation on this checkout.
- **Consumer adapters, not just helper contracts.** New tests cover the atomic-write mode policy and failure cleanup, the archive copy's verify-before-replace order, the frozen-design refusals, the zero-observation coverage row, the observation-identity refusal, the phantom-child refusal, the float64 likelihood widening, the shared donor plan and its column-label translation, and the tree builder's refusal of an asymmetric, negative or non-zero-diagonal matrix and of Euclidean-only linkage. The research report's shared include is executed and driven through present, missing and unparsable states, including a non-finite JSON token, a header-only CSV and the withheld-table path. Two end-to-end Quarto renders cover a truncated gate (named in the badge, tables withheld) and a corrupt result table under a clean gate (recorded, and every scientific table rendered after it withheld).
- `uv run --locked pytest` passes 3,442 tests and skips one, the same test #661 skipped because its archived pre-#594 LF-006 fit is absent; `uv run mypy` checks 486 source files with no issues and `tests/test_type_coverage.py` passes, so the new `atomic_files` module is clean under the strict flags rather than exempted. Ruff, Markdown formatting and spelling pass. Representative notebook and report imports resolve against the installed release.
