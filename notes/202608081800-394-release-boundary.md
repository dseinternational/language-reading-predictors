# The release decision becomes an object (#394, design point 3)

**Date:** 2026-08-08. **Issue:** #394 (complete the statistical pipeline family split and artefact lifecycle refactor), design point 3 and acceptance criterion "report finalisation receives an explicit release decision before key findings are generated". **Change:** structural. The publication _policy_ is unchanged — every fit's `key_findings.json` is byte-identical — and what moves is where the decision is made and whether anything holds it.

## What was wrong

Whether a fit may publish findings was decided by four sequential branches inside `reporting.generate_key_findings`: is `diagnostics_summary.json` readable, did the sampling-quality gate pass, is `config.json` readable, does the treatment-effect robustness gate release. Each wrote its own payload and returned.

That is a real policy, correctly ordered, and `test_key_findings.py` covers its outcomes for every registered family. The problem is that it was not a _thing_. There was no object to hold, print, record or hand to anything else, so:

- **Finalisation could not receive a release decision.** `stages.finalize_report` called the function that writes findings and read a status string off the payload that came back. The acceptance criterion asks for the opposite order.
- **Nothing recorded the reasoning** except where it happened to suppress findings. A fit that released cleanly left no statement that it had been asked; the `release` block appears in `key_findings.json` only for the five gated families.
- **The required/optional artefact split had no consumer.** `artifacts.py` has recorded `required` on every artefact since the interface landed, and design point 3 asks that a missing required output "fail the unpublished transaction or produce an explicit withheld release decision". Neither happened — the manifest reported it and finalisation carried on.

## What replaced it

`release.py` gains `ReleaseEvaluation` and `evaluate_publication`, one ordered decision in four stages, the first objection settling it:

1. **inputs** — `diagnostics_summary.json` and `config.json` present and readable.
2. **computation** — the automatic sampling-quality gate passes cleanly.
3. **artifacts** — every artefact the fit recorded as _required_ is on disk.
4. **robustness** — the treatment-effect prior-sensitivity and floor-grid policy, for the families it covers.

The order is the substance, not a formality. The gate outranks everything, so a reader is never told a fit's outputs are incomplete when the real objection is that it did not converge; and a fit that failed to converge is not asked whether its prior sensitivity is acceptable. `test_the_gate_outranks_every_later_stage` pins that with a directory that would fail two stages at once.

`stages.finalize_report` now computes the decision, writes it to **`release_decision.json`**, prints it, and passes it to `generate_key_findings`. The generator no longer decides anything: it maps the decision onto a payload and builds sentences. Given no decision — as by `regenerate_key_findings.py` — it evaluates one over the stored directory, so the post-hoc contract is unchanged.

## Why a separate file rather than more of `key_findings.json`

`key_findings.json` answers "what may this fit say"; `release_decision.json` answers "why". Keeping them apart has two practical consequences. The findings file stays byte-identical, so no rendered report moves in a change whose whole claim is that the policy did not. And the decision is recorded for **every** fit, not only the five gated families — an ungated mechanism fit now states that it was evaluated and found publishable, which is a different fact from being silent.

## The artefact stage, and what it is worth today

The stage withholds when the fit recorded a _required_ artefact that is not in its output directory. Optional artefacts cannot withhold: a plotting backend hiccup already records its own failure through `guard_optional`, and that distinction is exactly what makes the check safe to add.

Stated plainly: **this stage is inert on every fit verified here.** Nothing in the suite currently produces a required-but-absent artefact, because `save_table` writes before it records. It exists for the case where a required output vanishes between its write and finalisation — which the manifest could already report and nobody acted on. I would rather add a check that is provably inert today than claim a criterion is met by prose.

A withhold a reader sees as a soft note is not a withhold, so `_key_findings.qmd` gains a branch for the new status that suppresses the result tables the way the robustness withhold does. `test_the_partial_renders_every_withholding_status` walks the statuses the evaluator can produce and requires each to have one — policy split across the pipeline, the readers and the Quarto partials is the defect this design point names, and a status falling through to the "not available" fallback would recreate it.

## Verification

Eight dev fits chosen to cross the decision's branches — `itt-001`, `itt-009` (floor rule), `gf-001`, `lf-001`, `did-001` from the gated families, `med-059`, `mech-056`, `surv-009` from the ungated ones — run from `main` in a detached worktree and again from this branch.

**161 of 161 comparable artefacts are byte-identical, `key_findings.json` included**, with `release_decision.json` the only addition. Every decision agrees with the findings payload it gated, names the same model, and is recorded as `written` in the manifest rather than untracked. `test_key_findings.py`'s existing tests pass unchanged, which is the strongest evidence that the policy moved rather than changed: they cover the gate interlock, the robustness withhold, missing-CSV degradation and the sentence cap for every family.

The recorded stages are worth reading, because they show the ordering doing work rather than merely being declared. Two fits reach the robustness stage — `itt-001` releases, `itt-009` is `robustness_unresolved` — and the other six stop at `computation`, because a dev-tier fit's short chains do not clear the ESS threshold. Three of those six are gated families, and they carry **no** robustness verdict: a fit that did not converge is not asked about its prior sensitivity. My first comparison script flagged exactly that as a fault, which is how I know the property is real and not an artefact of how I wrote the check.

Full suite, `ruff check src/ scripts/ tests/`, `mypy`, `npm run format:check` and `npm run spellcheck` pass.
